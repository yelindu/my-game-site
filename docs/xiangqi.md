# 中国象棋：本地双人与联机

从大厅点击“中国象棋”，先进入简洁的玩法入口，选择“本地对战”后才显示棋盘。两人在同一台设备轮流操作。黑方在上，红方在下，红方先行。点击当前方棋子后，绿色标记表示合法目标；点击标记完成移动或吃子，再点已选棋子可取消选择。棋子使用 280 毫秒的平滑移动动画，悔棋时也会移动；系统选择减少动态效果时关闭过渡。

## 已实现的规则

- 车直走，不能越子；马走日字，马腿被占用时不能走。
- 象走田字，检查象眼，不能过河；士与将帅限制在己方九宫。
- 炮普通移动不越子，吃子必须隔恰好一个棋子。
- 兵卒只向前走，过河后可横走，不能后退。
- 不能走到己方棋子的位置，不能送将或让将帅照面。
- 被将军后，只允许解除将军的走法。
- 对手没有合法走法时判负：被将军为将死，否则为困毙。

基本走法与胜负规则参考 [世界象棋联合会规则](https://www.wxf-xiangqi.org/images/wxf-rules/2018_World_XiangQi_Rules_English2018.pdf)。本版提供休闲玩法，不自动裁判比赛中的长将、长捉、循环局面、自然限着或超时；双方可协商后点击“和棋”，再确认结束。

## 对局控制

“悔棋”恢复上一手的棋盘、被吃棋子与轮次，包括撤回将死或困毙结算。“重新开始”清空本局，有走棋记录时需页面内确认。“和棋”同样需要双方确认，取消不会改变对局。

状态仅保存在当前页面，刷新或返回大厅后重新开局。棋盘适配手机；本地双人不调用云端房间接口。

## 验证

`npm test` 检查标准开局、轮次、非法输入、吃子与悔棋、车炮阻挡、马腿/象眼、红黑过河和九宫限制、送将/照面/应将、将死/困毙、和棋后停止走子。

浏览器还需检查选择与目标提示、实际吃子、轮次变化、悔棋、确认和取消、重开、手机布局及大厅返回。`npm run build` 检查生产构建；发布由已有 GitHub Pages 工作流执行。

## 邀请朋友联机

进入象棋后点击“创建房间”，先进入选座等候区。点击“邀请好友”复制链接，也可在入口输入八位房间号。朋友打开邀请后自动进入房间。邀请链接包含 `game=xiangqi`，与已有五子棋链接区分。

红黑座位均可选择；未入座时为观战状态，开局前可离开座位或换座。双方入座后，房主点击“开始游戏”才显示棋盘。名字可直接修改，不提供微信、QQ 或其他账号登录。观战者在开局后能看到棋盘，但不能走棋或同意和棋。

游客身份保存在原浏览器；刷新邀请页面后自动恢复房间与座位。使用另一台设备或独立浏览器作为对手，同浏览器的多个标签共享身份。清除网站数据或换浏览器后无法找回原席位。

棋盘由云端保存并实时同步；断线期间禁止走棋，重新连接后读取完整棋盘。只有当前轮次玩家能提交合法走法，过期版本与重复提交会被拒绝。未加入房间的人不能读取对局；通过邀请码加入的第三人可观战，不能抢占已有座位或提交走棋。

“请求和棋”需由对方点击“同意和棋”；也可拒绝或撤回。继续走棋会撤销当前请求。联机暂不提供悔棋和同房间重开，新一局请返回房间入口并创建新房间。长将、长捉、循环局面和限时仍由双方协商。

## 云端配置与测试

在现有 Supabase 项目执行 `supabase/migrations/20261001010000_xiangqi_rooms.sql` 一次。该事务新增两张独立表、七个私有规则函数与五个玩家接口，启用 RLS 并加入 Realtime publication。已有游客登录及发布环境变量继续使用。

再执行 `20261001020000_xiangqi_lobby.sql` 一次，增加房主、昵称、房间成员和选座/开始接口，并保留旧接口与已进行的对局。房间成员只能通过接口登记，浏览器不能直接写入房间或抢座。

`npm run test:xiangqi-online` 使用 `.env.local` 验证真实游客、选座/离座、房主开局、观战、RLS、直接写入拒绝、实时事件、非法走棋、版本校验及双人和棋。会留下三个测试游客和一个测试房间，不删除用户数据。

`node scripts/check-xiangqi-db.mjs <临时安装的PGlite模块路径>` 验证基础 SQL 权限与规则。`check-xiangqi-lobby-db.mjs` 验证旧对局升级、昵称、抢座、房主开局、观战权限及五子棋兼容。`npm run test:render` 检查象棋入口和等候区不提前显示棋盘、无登录与规则介绍，以及本地棋盘的稳定棋子图层。
