# 谁是卧底

入口继续使用简洁的“本地聚会 / 创建房间 / 房间号加入”。本地聚会适合同处一桌的朋友，联机版使用文字描述，无需注册账号或第三方登录。

## 本项目采用的规则

- 4–6 人有 1 位卧底，7–8 人有 2 位。平民获得同一个词，卧底获得一个相关的不同词。两组词随机交换，玩家开始时只看到词语，不会知道自己的身份。
- 按座位顺序，每位在场玩家描述一次，描述为 1–120 个字，不可直接写出自己的词语。可以跳过；联机房主也可以跳过长时间未发言的玩家。
- 所有人发言后，仍在场的玩家分别投票，不能投自己。投完前只公布谁已投票，不公布投给谁；自己可以恢复查看自己的选择。
- 得票最多且唯一的玩家出局并揭晓身份。第一次平票时，只在平票玩家中重投一次；再次平票则无人出局，进入下一轮描述。
- 所有卧底出局，平民获胜；仍有卧底且在场人数降至 3 人，卧底获胜。结束后揭晓所有词语和身份。
- 联机房主点击“再来一局”返回同一个房间等候区，可调整座位后重新开始。

## 本地聚会

选择人数并修改名字，点击“开始分词”。设备交给指定玩家，点击“我已接过设备”后才能查看词语。点“隐藏并交给下一位”后会遮住内容，再传递给下一位。描述和投票也使用同样的交接流程。本地模式使用一台设备的内存，刷新会丢失本局，离开后不保存词语；同一设备的使用者应遵守不查看开发工具的约定。

## 文字联机

房主创建房间，所有人通过邀请码或邀请链接进入，选择空座位并改名。至少 4 人入座后，房主可开始，最多 8 人；空座位可以保留。观战者只能看到公开描述和已结算的投票，不会取得私密词语。未结束的对局通过同一浏览器的匿名身份恢复；清除浏览器数据或更换设备会成为另一个身份。

本版不包含白板角色、电脑玩家、语音、聊天、自动倒计时和主持人查看全体词语。有人断线时可以等待其重连；房主可跳过发言，投票阶段仍需所有在场玩家投票。

## 数据层与验证

新增迁移 `20261002010000_undercover.sql`：`undercover_rooms` 存放公开状态，`undercover_room_members` 存放本人房间成员关系，`undercover_secrets` 存放私密词语、身份及未结算投票。三张表都启用 RLS；客户端无法直接读写私密表。只有公开房间表进入 Realtime，词语不会通过实时事件广播。快照函数核验成员身份，只返回自己的词语和投票；身份在淘汰或结束后才公布。

服务端锁定房间并验证操作。发言使用状态版本；投票使用递增的投票轮次标记，允许多人同时投票，并拒绝重复或旧轮次请求。房间重开也继续递增标记。

运行 `npm test`、`npm run test:render`、`npm run build`。本地数据库检查可运行：

```text
node scripts/check-undercover-db.mjs <PGlite 模块路径>
```

云端检查使用已有 `.env.local` 的公开客户端配置：`npm run test:undercover-online`。该检查创建一次测试房间和匿名测试身份，验证私密信息隔离、同时投票、实时事件、结束揭晓、刷新恢复和重开。不要把服务端密钥放进前端。
