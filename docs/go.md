# 围棋

第一版为 9×9 棋盘，沿用“本地对战 / 创建房间 / 房间号加入”入口。联机有黑白两个座位，可改名、邀请好友和观战，双方入座后由房主开始。

## 本项目采用的规则

- 黑方先行，轮流在空交叉点落子。棋盘上的棋子不移动；没有气的对方连通棋块被提走。
- 先提掉对方无气棋块，再检查自己的棋块是否有气，因此提子后有气的落点允许落子。禁止落子后自己仍无气。
- 使用全局同形禁止：落子和提子后，不得形成本局此前出现过的完整棋盘。停一手不受重复棋盘限制。这是本项目明确选择的重复规则，不声称完整执行某个协会的竞赛规则。
- 白方贴 7.5 目；采用面积计分（存活棋子＋仅由己方围住的空点），黑白都接触的空区为中立点。提子数量展示为记录，不重复加入面积分。
- 双方连续停一手，进入终局确认。点击棋子可整块标记为死子，再次点击取消。改动标记会清除此前的双方确认；双方确认当前标记后，按移除死子的棋盘结算。
- 有死活争议，任一对弈者可恢复下棋，保留原棋盘和重复历史，清除死子标记及确认。恢复后的行棋方与连续两次停一手前相同。
- 对弈者可认输；结束后房主可“再来一局”，返回等候区调整座位。本地可确认后重新开始。

基本提子、终局协商和面积计分可参考[美国围棋协会规则说明](https://www.britgo.org/rules/agarules.html)。本项目没有传递停着棋子等 AGA 专用流程，最终以以上项目规则为准。

## 范围

目前没有电脑对手、13/19 路棋盘、让子、计时和自动死活判断。死子需要双方协商确认。本地刷新会丢失本局；联机使用原浏览器的匿名身份可恢复房间，更换设备或清除浏览器数据会成为新身份。

## 数据与验证

迁移 `20261002020000_go.sql` 新建 `go_rooms` 和 `go_room_members`，均开启 RLS，仅房间成员可读取公开状态，只有服务端操作函数可以更改棋盘。所有落子、停着、死子修改、确认和恢复均锁定房间并核对状态版本。观战者不能操作，旧状态的确认不能用于新死子方案。仅公开房间表进入 Realtime。

运行 `npm test`、`npm run test:render`、`npm run build`。本地 SQL 检查为 `node scripts/check-go-db.mjs <PGlite 模块路径>`，包含提子、禁入点、打劫、终局协议、权限和 400 次 JS/SQL 随机落子对比。云端检查为 `npm run test:go-online`，使用 `.env.local` 的公开客户端配置创建匿名测试身份和测试房间。
